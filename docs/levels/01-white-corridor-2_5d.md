# 白色走廊 2.5D 交互与验收

## 节点和排序

WhiteCorridor 运行时建立 World_YSortedByBase。登陆椅、四个年龄节点、侧门、出口和 Player_FeetSort 都是 DepthObject(Node2D)。每一个物件的 position 是脚底/基座，z_index 是该基座的整数 Y；玩家的 z_index 在每次移动后更新为 int(player.y)。所以角色在物件前方（更大的 Y）时覆盖物件，在物件后方（更小的 Y）时被其遮挡。

DepthObject 的 position 是唯一的排序和碰撞锚点，透明 PNG 子 Sprite2D 会向上偏移，令贴图下缘落在基座。正式物料位于 `assets/props/white_corridor/`：登陆椅终端、4 列年龄节点图集、两扇门图集、4 列证据图集，以及 4×2 的玩家/Ghost 地图角色图集。运行时用 AtlasTexture 精确分区，避免串格；终端、节点、侧门、出口、玩家及 Ghost 都不再用程序方块绘制。终端、侧门和出口使用 43px 基座半径，年龄节点使用 34px 基座半径；高大的视觉部分没有整块矩形碰撞。Ghost 是 `Ghost_MapActor` 的非碰撞浮动地图角色。若角色初始位置贴近基座，碰撞仅阻止继续深入，允许向外离开，避免出生点卡死。背景与顶栏由 WhiteCorridor 固定绘制，HUD 的 z_index=4096，均不参与 Y 排序。

## 空间和交互

## 意识接入序章与漫画对白

进入本关先进入 `BLACKOUT → DIALOGUE → RISING → EXPLORE` 的明确状态机。探索状态以前，WASD、Q 和 E/Enter 均不会移动角色或推进终端；E/Enter、Space 与点击漫画对白框只会逐页推进 Ghost 的接入说明。`lying_therapist.png` 是独立的透明躺姿图层，固定叠放在登陆椅上，站姿角色开场透明；最后一页以淡出躺姿、淡入站姿的短 Tween 完成起身，随后把玩家放到椅旁并开放控制。输入在状态切换后等待一帧，避免最后一次确认同时触发终端。

`ComicDialogueLayer` 是 `view.gd` 创建的固定屏幕组件，不参与世界 Y 排序。它包含 Ghost/人物的胸像裁切、青色描边的漫画框、说话人名、底部对话与继续提示，并带有速度线装饰。**本轮仅白色走廊和成长档案室实际接入**：第一关使用它完成完整序章；第二关在父亲、林澈的已说出口对白以及关键 Ghost 说明时使用。系统错误、任务 HUD、近距提示和解谜模态仍保留普通文字；第三关及以后仅保留组件基础，不迁移现有对白。

玩家可在 x=82..1200、y=332..546 内使用 WASD/方向键作真实二维移动。每个交互物件的半径为 78px；E 以及辅助调用都会先检查距离。鼠标/辅助调用 click_station 只设置走近目标，不会远程推进。

状态机：终端 → 7岁(Q 发现后打开蓝色碎片物证) → 15岁(录取通知书压住报名表 → 移开 → 展开 → 阅读) → 18岁(阅读父亲／老师／亲友来源 → 玩家选择“外部期待，无法替代自我意愿”) → 22岁(阅读无原始语音和记忆纹理的系统摘要 → 玩家选择“标记为系统摘要并移除”) → 4/4出口 → archive_room。任何物证确认前都不能推进；18、22 的错误选项会显示确切来源冲突且停留在选择层。Q 会显示各未恢复节点的真实证据层；已恢复的证据层可持续查看。侧门始终显示权限不足，18和22岁意愿仍写入“无法确认意愿”。

## 漫画物证特写与主体性

`EvidenceInspectLayer` 是固定屏幕 UI（z=4096），暗化场景后用独立金色边框呈现大图、标题、可读正文、来源注释及移开／展开／确认操作；它不复用人物的 `ComicDialogueLayer` 对白框。E、Enter、Space 或按钮可移开并展开纸张，再确认阅读。18、22 岁在关闭物证后切换为三个可点击的证据判断选项；Ghost 只用“来源来自谁？”、“你找到原始记录了吗？”等问题引导，不替玩家宣布人格或职业结论。

## 验收

1. 远离终端或年龄节点按 E，确认 Ghost 提示先靠近。
2. 在同一节点上方、下方各站一次，角色 z_index 应跨过该节点基座 z_index。
3. 按住 Q 才能推进 7 岁第一步；按顺序完成四节点。
4. 18岁后走近 MEMORY DELETED，确认拒绝进入；4/4 后走近出口才进入第二关。

white_corridor_smoke.gd 覆盖正式物料加载、躺姿图层、开场锁定、漫画对白逐页推进、起身后控制解锁、实际 Ghost 地图渲染、远距拒绝、Q 证据层限制、节点顺序、前后排序和出口状态。`six_scene_playthrough.gd` 会在每一轮先完成序章，再验证完整六关链路。
